# Sample WAV test set

Fifteen small, labelled, deterministic WAV files for exercising the upload path of the
app and for developing a real detector. All files are 16-bit PCM, 2 s long, and are
regenerated byte-for-byte by:

```bash
python scripts/generate_sample_wavs.py            # writes into data/samples/
python scripts/generate_sample_wavs.py --duration 5 --out /tmp/long_samples
```

`manifest.csv` lists every file with its machine profile, condition label
(`healthy` / `fault` / `edge_case`), fault type, sample rate, channel count, seed,
burst amplitude, noise level and purpose. Use it as the label source for batch
evaluation (ROC / precision-recall) once the detector is scored on measured features.

## What is in the set

| Group | Files | Why it exists |
| --- | --- | --- |
| Healthy / fault pairs | `robotic_arm_*`, `stamping_press_*`, `conveyor_drive_*` (`_healthy_48k`, `_fault_48k`) | Same signal model as the in-app simulator (base tone, 3rd harmonic, white noise, damped 22 kHz bursts). The fault files use the same burst parameters as the "Inject Micro-Crack Anomaly" toggle. |
| Detection-floor cases | `robotic_arm_fault_weak_48k` (burst amplitude 0.10), `robotic_arm_fault_noisy_48k`, `robotic_arm_healthy_noisy_48k` (noise std 0.12) | Threshold and SNR studies. A detector that only measures energy above 20 kHz cannot separate the two noisy files; a real feature set must. |
| Input-validation cases | `robotic_arm_fault_stereo_48k`, `robotic_arm_fault_clipped_48k` (39% of samples clipped), `robotic_arm_fault_16k` (Nyquist 8 kHz, fault aliases), `silence_48k` | The app must down-mix stereo, flag clipping, refuse to score a file whose sample rate cannot contain the diagnostic band, and reject silence instead of reporting a score. |
| Physically motivated bearing fault | `bearing_outer_race_healthy_48k`, `bearing_outer_race_fault_48k` | Impacts at the outer-race defect frequency (shaft 29.95 Hz x 3.585 = 107.4 Hz) ringing a 5.2 kHz structural resonance with 1.5% slip jitter. This is what a real bearing defect looks like: it carries no energy above 20 kHz and is only visible through envelope / kurtosis analysis in a mid-frequency band. |

## Measured behaviour (reference values)

Values below were produced by loading each file exactly as the app does
(`librosa.load(path, sr=None, mono=True)`).

| File | Current app score* | 20-24 kHz band power / total (dB) | Envelope peak 3-8 kHz band (Hz) |
| --- | ---: | ---: | ---: |
| robotic_arm_healthy_48k | 29.0 | -26.4 | - |
| robotic_arm_fault_48k | 29.0 | -16.8 | - |
| robotic_arm_fault_weak_48k | 29.0 | -24.7 | - |
| robotic_arm_fault_noisy_48k | 29.0 | -11.3 | - |
| robotic_arm_healthy_noisy_48k | 29.0 | -11.8 | - |
| robotic_arm_fault_clipped_48k | 29.0 | -20.9 | - |
| robotic_arm_fault_16k | 7.0 | n/a (band above Nyquist) | - |
| silence_48k | 7.7 | -7.7 (flat noise floor) | - |
| bearing_outer_race_healthy_48k | 29.0 | -22.0 | 35 |
| bearing_outer_race_fault_48k | 29.0 | -22.4 | 105 (BPFO = 107.4) |

\* `calculate_anomaly` with the demo boost off. The un-normalised mean FFT magnitude
saturates the +22 cap for every 2 s upload, so the current detector returns 29.0 for
healthy and faulty files alike; the 16 kHz file silently returns the 7.0 floor. These
numbers are the baseline the detector rewrite is measured against.

## Public datasets for real recordings

None of these are redistributed here; download them yourself and check the licence.

| Dataset | Signal | Sample rate | Format | Licence | Fit for this app |
| --- | --- | --- | --- | --- | --- |
| [MAFAULDA](https://www02.smt.ufrj.br/~offshore/mfs/page_01.html) (UFRJ) | Microphone + 6 accelerometers + tachometer; normal, imbalance, misalignment, inner/outer bearing faults; 1,951 x 5 s | 50 kHz | CSV (8 columns, column 8 = microphone) | Not stated upstream; research use with attribution, do not redistribute | Best match: real acoustic channel above 40 kHz sample rate with bearing labels. The Shure SM81 rolls off at 20 kHz, so real faults must be detected below 20 kHz (envelope analysis), not in the 20-24 kHz band. "Normal" subset is 0.3 GB. |
| [ToyADMOS2](https://zenodo.org/records/4580270) (NTT) | Miniature machine sounds, normal + anomalous, multi-mic | 48 kHz | WAV | NTT evaluation licence (DCASE subsets: CC BY-NC-SA 4.0) | Directly loadable WAVs; toy machines rather than industrial bearings. |
| [DCASE 2021/2023 Task 2 dev sets](https://zenodo.org/records/4562016) (Hitachi + NTT) | 7 real/toy machine types, 10 s clips with factory noise | 16 kHz | WAV | CC BY-NC-SA 4.0 | Realistic noise, but 16 kHz means the app's ultrasonic band is empty; use only after the detector supports configurable bands. |
| [CWRU Bearing Data Center](https://engineering.case.edu/bearingdatacenter) | Accelerometer (vibration), seeded inner/outer/ball faults | 12 kHz and 48 kHz (drive end) | MATLAB `.mat` | Not stated; freely downloadable, cite CWRU, do not redistribute | Canonical bearing benchmark with known BPFO/BPFI; needs a `.mat` to WAV converter (scale to +/-1). |
| [Paderborn KAt](https://mb.uni-paderborn.de/en/kat/research/kat-datacenter/bearing-datacenter) | Vibration + motor current, artificial and real damage | 64 kHz | MATLAB `.mat` | CC BY-NC 4.0 | Real (run-to-failure) damage; needs conversion. |

A small `.mat`/CSV to WAV converter and a MAFAULDA loader are natural follow-ups so that
the app can score real recordings without manual preprocessing.
